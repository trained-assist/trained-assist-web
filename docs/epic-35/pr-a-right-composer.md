Эпик: https://github.com/trained-assist/trained-assist-web/issues/35

Статус: постановка для будущей реализации. В этом подготовительном коммите нет изменений приложения или тестов. Не считать его выполнением этапа и не сливать вместо реализации.

## Результат и границы

Один интерфейс ввода сообщения справа, используемый для новой сессии и ответа в существующую. Слева — навигация и максимально высокий список сессий. Центр — история и стрим. Никакой второй, в том числе скрытой, формы создания.

Рабочая область этапа: `src/index.html`, `src/style.css`, `src/app.js`, `test/web-ux.mjs`, UI-разделы `docs/ACCEPTANCE-TESTS.md`. При необходимости выделить небольшой controller/store без смены фреймворка. API, worker, деплой и инфраструктуру в этом этапе не перепроектировать. Ошибки контракта передавать этапу B.

Перед реализацией прочитать эпик, PR #19, #25, #26, #28, #30, #31, #34 и текущий `CLAUDE.md`. Не восстанавливать старый код #25 слепым revert: сохранить последующие исправления.

## UX-контракт

- В верхней части правой панели постоянно видна кнопка «+ Новая сессия». Нажатие не запускает агента и не создаёт пустую серверную сессию.
- Под кнопкой — явный адресат сообщения: «Новая сессия» либо название выбранной сессии. В новом режиме появляется выбор проекта и создание проекта; ниже используется тот же textarea, файл, микрофон и submit. Не размещать рядом второй reply.
- Предусмотреть действие «Вернуться к сессии»/отмену нового режима. Черновик сохраняется. Повторное открытие нового режима восстанавливает его. Если сессия не выбрана, показывать понятное пустое состояние; отправка не должна угадывать адресата.
- Просмотр центра и адресат composer связаны явными переходами, а не результатом случайного завершения загрузки. В новом режиме центр может сохранять прежнюю историю, но её нельзя принять за адресата новой задачи.
- После подтверждения новой сессии открыть её и переключить composer на reply, если пользователь за это время не ушёл в другой контекст. Поздний ответ не должен перехватывать навигацию.
- Справа оставить самостоятельный расширяемый блок контекста для будущих настроек/артефактов. Не реализовывать эти фичи сейчас и не отдавать всю высоту огромному textarea. Длинный ввод и контекст скроллятся без потери доступности кнопок.
- На мобильном вход в создание доступен и из списка, и из диалога; показывается тот же composer, а не его мобильная копия.

## Состояние: общий UI, раздельные черновики

«Один composer» не означает один общий текст для всех сессий. Нужен один controller/store с записями `new` и `session:<id>`, содержащими текст, вложения и применимый проект.

Синхронно сохранять прежний черновик и менять адресата до любого `await` или hashchange. Асинхронные загрузки, запись/расшифровка голоса и ответы API должны иметь captured destination/request token; устаревший результат не записывается в другой черновик. При смене адресата во время upload до mutation POST отменить отправку с сохранением исходного черновика. Уже отправленный запрос не повторять из-за ухода со страницы или обрыва стрима. Уход со стрима сам по себе не равен остановке задачи.

Фиксировать snapshot отправляемого текста/файлов/проекта. Очищать только подтверждённый snapshot, а не текст, дописанный пользователем во время запроса. Ошибка и отсутствие подтверждения не теряют данные. Busy-state не должен смешивать разные сессии.

## Чек-лист реализации и приёмки

- [ ] Удалены `create-panel`, `create-input`, create-specific file/chips/send handlers; разметка и pipeline ввода физически одни.
- [ ] На desktop `new-session` находится внутри `pane-actions`; открытие нового режима не меняет высоту/позицию `sessions-list` более чем на 1 CSS px при одинаковых данных.
- [ ] Старт без проекта, с существующим проектом и с только что созданным проектом работает через текущий API; ошибка обновления списка не отменяет успешно созданный проект.
- [ ] Один и тот же набор controls/testid используется в new/reply; сохраняется тот же DOM-узел textarea при переключении режимов.
- [ ] Текст, выбор файла, paste, drag-and-drop и voice/transcription проверены в обоих режимах; диктовка редактируется и сама ничего не отправляет.
- [ ] Цикл A → New → B → New → A восстанавливает правильные текст, файлы и проект; Cancel, повторный клик, browser back/forward не смешивают данные.
- [ ] Медленная загрузка A после перехода в B; навигация во время upload; поздняя расшифровка; поздний done; ввод во время отправки покрыты отдельными assertions.
- [ ] Click, Ctrl/Cmd+Enter и double-click вызывают ровно один нужный mutation POST; пустой ввод не отправляется.
- [ ] Upload failure, HTTP error, разрыв стрима и done без sessionId дают видимую ошибку и восстановимый draft, без auto-rePOST.
- [ ] Stop/Дополнить с подтверждением и отменой, Continue, import, поиск, фильтр проектов и reproject не регрессируют. В новом режиме Stop/Дополнить скрыты.
- [ ] Viewports: 1440×1000, 1280×844, 1024×768, 390×844. Нет горизонтального overflow и перекрытых кнопок; mobile не теряет вход в создание.
- [ ] Playwright проверяет расположение/единственность composer и реальные переходы состояний; старые assertions про отдельную левую форму заменены, а не просто удалены.
- [ ] `npm test` и `node --check src/app.js` зелёные на SHA реализации; приложены результаты и скриншоты new/reply на desktop/mobile.
